# BehaviorLab

**Beat the skeptic.** An evidence-based behavioral nudge simulator, played as a short game. Enter any policy goal and BehaviorLab researches the evidence, proposes interventions with uncertainty ranges, simulates them probabilistically, and has a skeptical reviewer challenge the result. Everything is also exposed to external AI agents through WebMCP.

> Before implementing a policy, which behavioral interventions are most likely to work, how uncertain is that, and how strong is the evidence?

## The game

Every goal becomes a mission with a budget:

1. **Mission.** For example "35% → 37% within 12 months, budget NPR 34 lakh", with a progress meter toward the target. The target is calibrated to what the *reviewer-adjusted* evidence says the best affordable portfolio can deliver (75% of it), so the mission is winnable, but only with a good portfolio.
2. **Spend.** Each intervention has a cost. The budget always affords two or three nudges, never all five, so you have to trade off. Over-budget rows are disabled.
3. **Bet.** Before anything runs you set how many percentage points you expect to actually gain. The slider starts at what the proposals claim; accepting that default is the optimist's mistake.
4. **Reveal.** The optimistic result fills the meter and looks like a win. Then the red pen strikes through each card in turn, the meter shrinks to the reviewer-adjusted result, and 5,000 simulated outcomes drop into a histogram with the target as a vertical line. *Skip* jumps to the score.
5. **Score.**
   - **Mission:** success if the reviewer-adjusted median reaches the target, plus the share of draws that do.
   - **Calibration (0–100):** how close your bet was to the reviewer-adjusted median gain. The error is scaled by the gain the optimistic simulation claimed.
   - **Efficiency:** percentage points gained per budget unit spent.
   - **Rank:** Optimist, Analyst, Skeptic or Red Pen, from your average calibration this session.
6. **Retry.** Swap one intervention and go again. Reviewer notes you have already seen stay visible.

Costs, budgets and horizons are illustrative planning figures generated by the model, not sourced data. When the goal mentions Nepal, costs are expressed in NPR (lakh).

## How it works

1. **Evidence discovery (Tavily).** Searches the web for behavioral-science research and policy experiments relevant to the goal.
2. **Scenario generation (Nemotron Super).** Builds a scenario with the target population, a baseline rate, and five interventions. Each has a low/medium/high effect estimate (percentage points), assumptions, and citations. An intervention is labelled **research-backed** only if it cites a returned source; otherwise it is a **hypothesis**. The baseline is labelled `user`, `evidence`, or `assumed`.
3. **Probabilistic simulation (`src/simulation/engine.ts`).** Runs 5,000 seeded Monte Carlo draws sampling a triangular distribution over each effect range. Effects are improvements toward the goal, so the engine raises the rate for an "increase" goal (VAT filing, vaccination) and lowers it for a "decrease" goal (vaping, abuse); Nemotron Super sets the direction per scenario. Reports the expected, median, 5th/95th percentile, worst and best case (relative to the goal), and the probability of improvement, rounded to at most one decimal and never above "over 99%". Combined nudges are simulated with a 20% diminishing-returns discount per extra nudge.
4. **Critical review (Nemotron 3 Ultra).** Acts as a skeptical policy reviewer: evidence strength, comparability of the research to the target population, realism of the effect range, concerns, a realistic range of its own, and recommended combinations. The review also runs once while the scenario is built, to calibrate the mission target; its notes stay hidden until the reveal. Results are shown as **Optimistic** (Super's ranges) and **Reviewer-adjusted** (Ultra's ranges).

The page starts empty. An illustrative recycling scenario exists only as the offline default for WebMCP agents before any scenario is generated; in the UI, recycling is just one of the example goals.

## Quick start

Prerequisites: Node.js 18+ and npm, a [Tavily](https://tavily.com) API key, and a [Nebius Token Factory](https://tokenfactory.nebius.com) API key.

```bash
git clone <repo-url>
cd Behavioral-lab
npm install
cp .env.example .env.local   # then add your two keys
npm run dev
```

Open <http://localhost:3000>:

1. **Goal.** Type a goal or click an example chip, then **Build scenario** (about 30 seconds; the page shows real progress: searching, reading sources, drafting, then setting a target).
2. **Spend.** Tick interventions within the budget.
3. **Bet and reveal.** Set your bet, **Lock in bet and run simulation**, and watch the reveal and score.

Restart `npm run dev` after changing `.env.local`.

## Configuration

Set in `.env.local` (see `.env.example`). Keys are only read by the server routes `/api/scenario` and `/api/critique`.

| Variable | Required | Default |
| --- | --- | --- |
| `TAVILY_API_KEY` | yes | |
| `NEBIUS_API_KEY` | yes | |
| `NEBIUS_BASE_URL` | no | `https://api.tokenfactory.nebius.com/v1` |
| `NEBIUS_SUPER_MODEL` | no | `nvidia/nemotron-3-super-120b-a12b` |
| `NEBIUS_ULTRA_MODEL` | no | `nvidia/Nemotron-3-Ultra-550b-a55b` |

Model IDs must exist on your Nebius account. List them with:

```bash
curl -s https://api.tokenfactory.nebius.com/v1/models -H "Authorization: Bearer $NEBIUS_API_KEY"
```

A "model does not exist" (404) error means the ID needs overriding.

## Caching

Paid calls are cached on the server so repeating a goal makes no API calls (first build is about 30–50 seconds; a repeat is under a second):

- **What:** Tavily evidence, the Nemotron Super scenario, and the Nemotron Ultra critique.
- **Where:** in memory plus JSON files in `.cache/behaviorlab/` (gitignored), so results survive restarts. On a read-only filesystem it falls back to memory only.
- **Key:** goal, target, baseline, model IDs, source URLs and a prompt version, normalised for case and spacing. Changing a prompt or model never serves stale results.
- **Also:** concurrent identical requests share one upstream call, and failures are never cached.
- **Fresh data:** the page shows "Loaded from cache" with **Rebuild with fresh research**; the `generate_scenario` tool takes `refresh: true`.

| Variable | Default | Effect |
| --- | --- | --- |
| `CACHE_DISABLED` | unset | `1` bypasses the cache entirely |
| `CACHE_DIR` | `.cache/behaviorlab` | where files are stored |
| `CACHE_TTL_HOURS` | `168` | expiry (7 days) |

## WebMCP tools

Registered in the browser on page load via `document.modelContext`, so any WebMCP-compatible agent can drive the app. Tools operate on the active scenario, which is shared with the UI.

| Tool | Purpose |
| --- | --- |
| `generate_scenario` | Define a goal (optional `target`, `baselineRate`); runs Tavily + Nemotron Super and replaces the active scenario. |
| `get_scenario` | Active goal, target, baseline (and its basis), context, and sources. |
| `list_interventions` | The five interventions with effect ranges, evidence type/strength, assumptions, citations. |
| `run_simulation` | Monte Carlo simulation of one intervention (`interventionId`, optional `trials`). |
| `compare_interventions` | Ranks 2+ interventions with uncertainty ranges; `includeCombination` also simulates them together. |
| `explain_result` | Nemotron Ultra's critical assessment (cached after the first call) of an intervention, its realistic range, and recommended combinations. |

Intervention IDs are generated per scenario. Use the ids from `list_interventions`.

## Limitations

- Effect ranges are model-generated estimates grounded in whatever Tavily retrieves. They are not causal predictions, and the simulation says so.
- Baselines are often assumed, since many contexts have no measured rate. The UI flags this.
- Results vary between generations. The reviewer's ranges are a second opinion, not ground truth.
- Evidence is frequently from other countries. Check the reviewer's comparability notes.
